# 视觉基线

这份不讨论审美流派，只解决三件事：**颜色统一、层级清楚、不同页面长得像同一个产品。**

**读法：默认值优先。** 表里给的值直接用，不要重新设计。只有用户明确要求某种风格时，才在默认值之上调整。

**这份和 `design-spec.md` 的分工**：本节是"值怎么选、丑了怎么改"的参考手册，给的是可用的起始值；项目一旦定了 `02视觉风格/design-spec.md`，**那份才是真值来源**，本节退回参考位。两处值不一致时以规范文件为准，并回改本节用到的默认值。

---

## 一、页面"丑"，通常是四个机械问题

不是没品味，是这四件事没有统一：

| 症状 | 实际原因 |
|---|---|
| 整页发灰、没有重点 | 所有文字字号和颜色差不多，层级差不够 |
| 看着乱、说不清哪不对 | 间距随手填：这里 20、那里 30、再那里 25 |
| 廉价感 | 阴影太重、圆角太大、每张卡片都带边框 |
| 每个页面像不同产品 | 各页各做一套，没有共用变量和骨架 |

**结论：先把这四件事统一，页面立刻从"丑"变成"正常"。** 审美是下一步的事。

## 二、先定 token，再写页面

这是"颜色不统一、圆角不统一"的**唯一根治办法**。事后检查永远补不完——今天统一了，明天加个新页面又散了。

### 最小 token 集（够管全部页面）

定在 `app.wxss`（或项目的全局样式入口），**只定这一次**：

```css
page {
  /* 颜色 —— 1 个主色 + 3 档文字 + 2 档底 + 1 条线 + 1 个危险色 */
  --c-primary: #E8734A;        /* 换成你的主色，全局只有这一个强调色 */
  --c-primary-soft: #FDEDE7;   /* 主色浅底：选中、标签、轻提示 */
  --c-text-1: #1A1A1A;         /* 标题、正文主信息 */
  --c-text-2: #666666;         /* 次要信息、字段名 */
  --c-text-3: #999999;         /* 辅助说明、时间、占位 */
  --c-bg-page: #F7F7F7;        /* 页面底色 */
  --c-bg-card: #FFFFFF;        /* 卡片/列表底色 */
  --c-line: #EEEEEE;           /* 分隔线 */
  --c-danger: #E54D42;         /* 删除、失败 */

  /* 字号 —— 五档，不现编 */
  --fs-page: 44rpx;            /* 页面主标题 */
  --fs-title: 36rpx;           /* 区块标题、卡片标题 */
  --fs-body: 30rpx;            /* 正文、列表主信息 */
  --fs-sub: 26rpx;             /* 次要信息、字段值 */
  --fs-note: 22rpx;            /* 辅助说明、时间戳 */

  /* 间距 —— 五档，全部从 8 的倍数来 */
  --sp-1: 8rpx;
  --sp-2: 16rpx;               /* 组内间距 */
  --sp-3: 24rpx;
  --sp-4: 32rpx;               /* 组与组之间 */
  --sp-5: 48rpx;               /* 区块与区块之间 */

  /* 圆角 —— 只有两档 */
  --r-sm: 12rpx;               /* 小元件：标签、输入框、小按钮 */
  --r-md: 24rpx;               /* 卡片、大按钮、弹层 */

  /* 阴影 —— 只有一档 */
  --shadow-1: 0 4rpx 12rpx rgba(0, 0, 0, 0.06);
}
```

**这一份定完，后面所有页面只引用，不写字面值。**

### 强约束：这三个字面值不许出现在页面里

| 禁止 | 改成 |
|---|---|
| `#333` `#E8734A` 这类裸颜色 | `var(--c-text-2)` |
| `32rpx` 这种裸间距 | `var(--sp-4)` |
| `border-radius: 20rpx` 现编圆角 | `var(--r-md)` |

例外只有三种：`0`、`100%`、`1px` 描边（描边用 `1px`，不要用 `2rpx`——2rpx 在不同 DPR 机型上粗细不一致）。

## 三、主色怎么选（不用懂配色）

小程序最省事的做法：**选一个主色，其余全部由它派生。**

### 三步

1. **主色从三处取一个**
   - 产品品类联想（做饭 → 暖橙；记账 → 稳绿；工具 → 蓝）
   - 品牌已有的色
   - 参考产品的色，但**色相至少偏 30°**，避免撞脸

2. **饱和度压一档**
   小程序主色不要太艳。大面积用主色会很刺眼，所以：主色只用在**按钮、选中态、少量强调文字**；大面积底色一律用 `--c-bg-page` / `--c-bg-card`。

3. **浅底用主色透明度派生**
   `--c-primary-soft` = 主色 8–12% 透明度叠在白底上。选中行、标签背景、轻提示都用它，**不要另找一个浅色**。

### 状态色是固定的

成功 `#07C160`、警告 `#FA9D3B`、危险 `#E54D42`、信息 `#576B95`。这四个不要自己调色，用户对它们有固定认知。

**重要状态不能只靠颜色区分**——选中的行除了变色，还要有勾选标记或字重变化。

### 小程序特有的"颜色不同步"坑

导航栏和 tabBar 的颜色**写在 `app.json` / 页面配置里，读不到 CSS 变量**，而且是十六进制：

```json
{
  "window": {
    "navigationBarBackgroundColor": "#FFFFFF",
    "navigationBarTextStyle": "black"
  },
  "tabBar": {
    "color": "#999999",
    "selectedColor": "#E8734A",
    "backgroundColor": "#FFFFFF"
  }
}
```

**这是小程序最常见的不一致来源**：改了 CSS 主色，忘了改 `app.json`，结果按钮是新的橙色、tabBar 还是旧色。

规矩：**改主色时两处一起改，并在交付说明里写明改了哪两处。** 另外 `navigationBarTextStyle` 只接受 `black` / `white`，不支持任意色值。

### 深色模式

如果要做，用 `theme.json` + `darkmode: true`，**不要写两份样式**。如果这版没要求，就不做——半套深色比不做更糟。

## 四、层级：每屏只有一个主角

三条杠杆，按威力排序：

| 杠杆 | 怎么做 | 注意 |
|---|---|---|
| **字号差** | 相邻层级至少差 **6rpx** | 30 和 32 等于没有差别，是白费 |
| **颜色对比** | 主文 `--c-text-1`、次要 `--c-text-2`、辅助 `--c-text-3` | 别只用颜色区分，也别只用字号区分，两个一起用 |
| **留白** | 组内 `--sp-2`、组间 `--sp-4` | 不要靠加分割线来分区 |

**反例**：所有文字 `30rpx` 加粗 —— 全部都强调，等于全部不强调。

**每屏只有一个主角**（最重要的一条信息或一个动作），其余全部降级：更小的字、更浅的颜色、更靠边的位置。

## 五、页面骨架：只有四种排法

**这是解决"每页风格不统一"的关键**——不是定风格，是定骨架。同一个产品里，同类页面用同一个骨架，视觉自然就一致了。

### 1. 列表页（最高频）

```
顶部：一行标题（44rpx），高度约 96rpx，不要大标题 banner
可选：分段/筛选（一行，横向滚动）
列表：每项高 112–140rpx，左图右文 或 上文下辅
底部：主按钮（固定，避开安全区）或不做
```

- 列表项之间用 `--c-line` 的 1px 分隔线，**左右缩进对齐文字起始位置**
- 首屏露 **3–5 条**即可，不要为了"填满"塞 10 条
- 列表项自己**不加圆角、不加边框、不加阴影**（这些交给卡片形态，见下）

### 2. 表单页

```
按照"一组输入"分段，每组 3–5 项，组间 --sp-4
每项：标签在上（26rpx，--c-text-2）→ 输入在下（30rpx）
主按钮：全宽，高 88rpx，贴底，底部留安全区
```

- 标签**不要放在左边做两列表格**——中文标签长度不齐，一定歪
- 必填项用一个 `*` 就够，不要写"（必填）"
- 错误提示写在输入框下方，`22rpx` + `--c-danger`，**不要用弹窗报表单错**

### 3. 详情页

```
主信息区（大图或大数字）→ 关键字段（2 列）→ 正文分段 → 底部操作条
```

- 关键字段用"上标签下值"的两列网格，不要做成表格
- 底部操作条固定，避开安全区；超过 2 个操作时，第二个收进"更多"

### 4. 空状态

```
一句说明（30rpx，--c-text-2）+ 一个主按钮
```

- **不要配大插图**——画得不好比不画更糟
- 说明要告诉用户下一步能做什么，不是"暂无数据"
- **用能笑一下的口语写**：「这儿还空着 · 先扔一句话进来，分类的事回头再说」比「暂无记录」多留住一个人。写法见 `copywriting.md`

## 六、默认控件样式

### 按钮只有四种

| 类型 | 样式 | 用在哪 |
|---|---|---|
| **主按钮** | 实心主色、白字、`--r-md`、高 88rpx | 一屏只有一个 |
| **次按钮** | 白底 + 1px 主色描边 + 主色字 | 与主按钮并列时 |
| **文字按钮** | 主色文字，无底无边 | 次要动作、"查看更多" |
| **危险按钮** | `--c-danger` 字或底 | 只在删除确认里 |

**一屏出现两个实心主按钮，就是设计错误**——用户不知道该点哪个。

### 卡片还是列表

**默认用列表 + 分隔线。** 只有内容需要"独立成块"时才用卡片（带图片、多字段、可单独操作）。

整页全用卡片 —— 这是最典型的"AI 味"，也是页面显乱的常见原因。

卡片用了就**只用一种容器表达**：边框、阴影、异色底，**三选一，不要叠加**。

### 图标

- 一个产品**只用一套**图标，不混用线性/实心/彩色
- 图标尺寸约为字号的 1–1.25 倍
- tabBar 图标必须是**本地 png**（81×81，≤40KB），不能用字体图标或网络图
- 陌生图标旁边必须有文字

## 七、八个具体症状，照单抓药

| 症状 | 原因 | 改法 |
|---|---|---|
| 整页发灰没重点 | 层级差不够 | 主标题拉到 44rpx，主色只留一处 |
| 拥挤 | 间距全是 16 | 组间拉到 `--sp-4`(32)，区块间 `--sp-5`(48) |
| 廉价感 | 阴影重、圆角大 | 阴影统一 `--shadow-1`，圆角不超过 24rpx |
| 每张卡都带边框 | 边框+阴影+底色三件套 | 只留一件 |
| 文字花花绿绿 | 用颜色代替层级 | 颜色只表达状态，层级交给字号和字重 |
| 按钮长得都不一样 | 没有统一组件 | 建一个 btn 组件，全局只有四个 variant |
| 图标一半线性一半实心 | 混用了图标库 | 只用一套 |
| 首屏塞满 | 想一屏讲完所有事 | 列表页露 3–5 条，其余靠滚动 |

## 八、禁止清单（可以逐条检查代码）

- 页面样式里出现裸十六进制颜色（token 文件除外）
- 一个页面出现 5 种以上字号
- 一个页面出现 3 种以上圆角
- 一屏出现 2 个以上实心主按钮
- 用 `px` 写尺寸（`1px` 描边除外），一律 `rpx`
- 用 `:hover`（小程序没有悬停态，见 `motion.md`）
- 卡片同时用边框 + 阴影 + 异色底
- 空状态用大插图代替说明文字
- 文案写"请输入内容 / 暂无数据 / 操作成功"这类系统腔（语气见 `copywriting.md`）

## 九、交付前自检

1. 页面里有没有裸写的颜色/间距/圆角？（搜 `#`、搜 `rpx`）
2. 这一屏的主角是哪个？三秒能说出来吗？
3. 相邻层级的字号差，够不够 6rpx？
4. 一屏有几个实心按钮？
5. 改过主色的话，`app.json` 里的 tabBar / 导航栏颜色跟着改了吗？
