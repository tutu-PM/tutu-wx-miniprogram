# 页面素材清单生成规则

这是一份给助手使用的通用规则，不是某个项目的素材清单。它的输入是一张指定的页面设计稿；输出是这张页面自己的 `素材.md`，或明确说明「本页无需单独建清单」。适用于小程序、App、网站及桌面应用，不预设配色、业务字段、平台格式或素材数量。

## 调用方式

> 请按本规则处理「{项目名}」的「{页面名}」。页面设计稿：{文件或附件}；可选参考：{PRD、设计规范、现有素材目录、目标平台}。先看图，再判断是否需要页面素材清单。需要则生成本页的 `素材.md`，只做拆解与交接，不生成图片、不改设计稿或代码。

一份规则可重复用于多个页面。默认输出到项目视觉资料下的 `页面素材/<页面名>/素材.md`，可服从项目已有目录；下文模板不作为一个空文件交付。每页只维护一份清单，不为同一页面的每个状态另建文件。已有清单先判断是否对应同一页；不覆盖未知文件，不自动迁移旧清单。若有多版图，以用户指定的版本为准；仅有探索稿则标明「暂定」，不擅自选为终稿。

## 1. 判断要不要建清单

**先把两件事分开问：这个界面的结构和行为能否复用？还原它需要哪些视觉资源？** 前者决定怎样写组件，后者才决定要不要生成 `素材.md`。框架决定可用的基础控件，不证明项目中已有符合终稿的业务组件。

### 按项目现状判断组件复用

| 现状 | 判断依据与写法 |
|---|---|
| 已有项目，能查看代码 | 查项目实际引入的组件库、组件定义及使用位置，再与 PRD 和设计稿核对结构、交互、状态及样式。能指出来源且满足本页要求，才写「已有，可直接复用」；有差异写「已有，需适配」。只知道框架、只看到同名文件或无法查看代码，写「待核对」，不假定已存在或必须重做。 |
| 从零开始，目前只有一页定稿 | 对照本页设计稿与已有 PRD。结构、行为相同，仅数据或图标不同的元素，可标「计划页内复用」；不标成全项目公共组件。**一页定稿就能拆这一页的素材**，无需先建工程、写组件或等其他页面画完。 |
| 从零开始，多页需求或设计稿可对照 | 跨页元素的用途、交互和状态规则一致，且能用同一结构表达时，标「跨页共用候选」，写明对应页面；仅外观相似不能作为依据。待后续页面确认，再统一引用同一组件或素材 ID。不为猜测的未来页面增加素材、预建全局组件。 |

例如，一页有三张同结构的统计卡，可以计划只写一种卡片。数字和标题由代码显示；内部三个图标仍要逐个查来源。反过来，即使一个按钮需要从零开发，只要它仅由文字、边框和底色构成，也不因此产生图片制作任务。

### 按视觉资源决定是否建清单

| 看稿后的发现 | 处理 |
|---|---|
| 有待制作、裁切、分层或适配的图，或需说明复用位置、展示基线、暗色变体、缺图回退等 | 建本页清单，即使只有一张关键图也值得记录 |
| 使用已有共享图，但需要本页特有的构图、裁切或状态 | 建简短清单，只记共享素材 ID／路径及本页差异，不再下相同的制作任务 |
| 已逐项确认无本页需制作、适配或交接的视觉资源（包括组件内部的图标、插画、贴图）；即使控件尚待开发也适用 | 不建空清单，回复一句理由。如为用户明确要求的全项目盘点，可在盘点结果里标「无需新增」 |

## 2. 怎样从设计图拆出素材

1. **认准范围。** 记录项目、页名、设计稿路径及版本（终稿默认在 `02视觉风格/设计图/`）；分清真实界面和看图用的外包装。设备边框、评审注释、画布背景不是产品资源。不顺便重设计页面。
2. **逐区问：撤掉这张图会损失什么？** 需要识别具体物件、保留真实材质、表达空间或品牌的，列为图片候选。数字、可变文案、状态标签、按钮热区、表单和布局由前端实现；不能把整屏截图或带字的整块卡片当素材。动态图表的数据层也不切成位图。
3. **先找已有，再开制作项。** 分类为「复用现有」「待新制」「已有原图、需处理」「运行时内容」「代码实现」。已有文件只有实际检查过才写可复用；只发现文件名则写待核对。用户照片、商品封面等运行时内容，写清显示区域与缺图回退，不因稿里出现几张样例就要求项目备齐所有图片。
4. **按会不会独立变化来分层。** 会因数据增减、换状态、滚动或响应式布局而独立变化的前景、背景和装饰分开；总是一起出现、一起缩放的固定物件不必拆碎。同一对象在多个位置或页面出现，沿用一个稳定素材 ID，只记录必要变体。
5. **每张图写到足以制作。** 写用途、主体、构图／留白、视角与光向、透明要求、对齐点、允许裁切处、明确不要的元素。尺寸从实际显示区和目标平台推导；未测量的值标「建议」或「待测」，不冒充定稿值。格式、倍率、包体限制以项目约束为准。
6. **把清单和实际交付分开。** 建议文件名不等于文件已存在。「待制」「待核对」「已验收」不可混用。原图保留，处理在副本上另存；外部资源记录来源、授权和署名条件。仅在另有制作授权时生成、下载或处理图片。

### 2.1 按视觉对象分类切图

同一页允许混用两类。这里的「切图」指为前端准备独立资源，不是把截图分成若干矩形贴回页面。整页还原与验证流程见 [design-to-code.md](design-to-code.md)。

**A. 2D 平面图：可以执行**

| 对象 | 处理规则 | 通过条件 |
|---|---|---|
| 搜索框、卡片、状态标签、按钮 | 动态文字、数字、底色、边框和热区由组件绘制；内部有独立图标才单列。 | 换文案、数字或状态不需要重新出图；图标大小不决定热区大小。 |
| 图标、标识、平面插画 | 优先复用符合定稿的源文件。只有扁平截图时，先判断分辨率及轮廓是否足够；够才从副本按轮廓裁，不够就重绘或索取源图。 | 保全轮廓、必要透明留白和对齐基线，不带邻格、文字、底色；低清裁片放大不算高清交付。 |
| 同系列图标及普通／选中态 | 使用统一画布、视觉大小和基线；只导出确有差异的状态，复用项不按页复制制作。 | 切换状态不跳位，实际显示尺寸下仍可辨认；透明素材同时检查 alpha 通道及最终页面底色上的白边。 |
| 平面背景／可重复装饰 | 仅在不能由普通布局准确表达时切图，声明等比、允许裁切或可平铺的方向。 | 换宽度不拉扁主体；重复单元相接没有明显断线。 |

导出以目标显示尺寸和设备像素比为依据，不固定全项目一律 2 倍或 3 倍。输出格式遵循目标项目的平台约束；本套小程序规则要求不透明位图用 JPG，需透明用 PNG，不用 WebP。先留存未修改的原始副本，再另存处理结果。参考裁片标作「仅参照」，可交付素材另列；在页面实际尺寸验证后才标「已验收」。

**B. 拟三维／3D 图：占位，待实际项目验收后补写**

靠空间纵深、遮挡、材质和光影成立的部分在对应页面的清单中标为「待验证」。本版不指定切几层、哪些用图、哪些用代码，也不把试验截图作为通过证据。后续凭终稿、目标设备实际画面和用户确认补写；普通按钮和文字即使叠在这类画面上，仍按 A 类处理。

## 3. 输出骨架：生成时填成该页自己的内容

```markdown
# {页面名}｜素材清单

项目：{项目}　视觉基准：{指定稿的链接或路径／版本／确认状态}
本页范围：{要还原的区域或状态}。平台约束：{适用项}。
切图分类：{逐项或按组标明 2D 平面／拟三维待验证；混合页不整页归为一类}。

## 素材清单
| ID | 页面位置与用途 | 处理方式、来源／共享 ID | 文件名或实际路径 | 交付规格与对齐要求 | 状态 |
|---|---|---|---|---|---|
| {稳定 ID} | {放在哪里、用来识别什么} | {复用／新制／处理／运行时} | {标明现有或建议} | {显示尺寸、格式、透明、裁切、基线等必要项} | {实际状态} |

## 不切图的部分
{点名最容易误做成图片的动态信息或控件。有复用判断时注明「已有可用／需适配／待核对／计划页内复用／跨页共用候选」及依据；组件内部仍需交接的图，指向上表素材 ID。无需另写整份组件清单。}

## 制作说明（有新制项才写）
{按 ID 给简报；同系列共写一次风格，单项只列差异。需生图时写单件素材提示词，不沿用整屏效果图提示词。}

## 页面验收与待确认
{在什么实际背景、尺寸、状态下检查；缺图如何回退；列出尚未核实的依赖。}
```

## 4. 交付前核对

- 图上的每个有意义的视觉对象，都能解释为「素材、运行时内容、代码或评审包装」之一；不为凑数发明素材。
- 同一共享图不重复生产；每个待制项有具体用途和合格标准；每个复用项指向真实来源或明确待查。
- 验收看真实显示尺寸和背景：边缘无白边、关键轮廓不裁掉、透明叠放无重影、相邻重复单元无接缝、不同数据量下不拉伸主体。只选本页相关项。
- 只写清单时，结论止于「清单已生成」；未实际制图、合成或真机查看，不写成已完成。
