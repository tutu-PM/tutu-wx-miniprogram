# 文案语气：一个产品一套口吻

适用于界面上的所有文字：页面副标题、输入框占位、按钮名、字段值、空状态、加载提示、成功提示、出错提示、确认弹窗、筛选无结果、设置项、引导语、授权说明。

---

## 零、这是产品级决定，不是每页的选择

语气在**开工时定一次**，写进 `02视觉风格/design-spec.md` 的「风格」一节，之后**全站所有页面执行同一套**。

定了"滑稽"，那就是**每一页的提示文案都是这个口吻**——不是首页贫、设置页正经。

判断标准很简单：**把全站文案抽出来排成一张表，遮住页面名读一遍，像不像同一个人写的。** 不像就是没做到。

只有两种例外：

| 例外 | 怎么处理 |
|---|---|
| **用户点名某一处要改文案** | 按用户说的来，并记进规范的「例外清单」，别下次又"统一"回去 |
| **安全红线位置**（出错、删除等方式不可逆的操作、金额、隐私授权） | 仍然用**同一套口吻**，只是不加笑点。见第三节——这不是换风格，是同一风格的低调档 |

除这两类，任何"这页太活泼了，我改正经点"的想法，都属于破坏一致性。

## 一、"滑稽"必须落成可执行的档位

"滑稽""幽默""有点意思"都是形容词，没法执行，也没法验收。定风格时要把它翻成下面这张表，写进规范：

| 参数 | 滑稽档取值 |
|---|---|
| 人称 | 你（全站不混用「您」） |
| 句长 | 主句 ≤ 12 字，一句只说一件事 |
| 禁用词 | 请、您、暂无、操作、成功、失败、确认、敬请、温馨提示 |
| 笑点来源 | 自嘲 / 把系统行为说成人话 / 日常物件做比喻（扔、搁、翻、捞、归队） |
| 标点 | 一段只留一个语气符号（问号、省略号、波浪号、感叹号挑一个） |
| emoji | 0 个。确实想加，只在低频位置加 1 个 |
| 比喻取材 | 生活里的动作和物件，不用网络梗、不用谐音梗 |
| 卖萌词 | 嘛、啦、呀 连用最多一个，不叠 |

**这张表才是"风格已定"的证据。** 只写"滑稽风格"四个字，等于没定。

---

## 二、全站要覆盖到哪些位置

定完档位，按这张表逐处落。新增页面时照这张表补，不重新想。

| 位置 | 字数上限 | 滑稽档怎么写 | 例 |
|---|---|---|---|
| 页面副标题 | 20 字 | 说人话，不用"待处理""未归类"这类词 | 「11月19日 周三 · 还有 2 条没归队」 |
| 输入框占位 | 12 字 | 说"干什么"，不说"请输入" | 「脑子里刚闪过啥？先丢进来」 |
| 主按钮 | 2–4 字 | 动词开头，口语 | 「记下来」而不是「保存记录」 |
| 次按钮 | 2–5 字 | 同上 | 「再试一次」而不是「重新加载」 |
| 字段值 | 2–6 字 | 用口语词，不用系统状态词 | 「还没做完」而不是「未完成」 |
| 分区标题 | 4–8 字 | 可以用生活化说法 | 「刚记下的」而不是「最近记录」 |
| 空状态标题 | 8 字 | 短、说现状 | 「这儿还空着」 |
| 空状态说明 | 30 字 | 说下一步，打消顾虑 | 「扔一句话进来就行，归哪类的事，回头再说」 |
| 加载提示 | 10 字 | 说正在干嘛 | 「正在翻本子…」 |
| 成功提示 | 10 字 | 说结果，不说"成功" | 「记下了」 |
| 出错提示 | 20 字 | 哪儿错了 + 怎么办（不加笑点） | 「没存上，检查下网络再试」 |
| 删除/覆盖确认 | 一句后果 | 说清不可逆（不加笑点） | 「删了就找不回来了」 |
| 筛选无结果 | 20 字 | 说清是筛出来的空，给动作 | 「这个筛法啥也没捞着，换个条件」 |
| 引导语 | 20 字 | 说收益，不说功能 | 「每天记一条，月底回头看」 |

**高频出现的（保存、完成、删除）越短越好，但口吻不变。** 短是为了快，不是为了变回公文腔。

### 不参与语气的部分

语气作用于**句子和动词**，不作用于**名字**。下面这些保持中立、清楚，不要为了好玩去改：

| 不参与语气 | 例 |
|---|---|
| tab 名、页面名 | 收集箱 / 工作 / 学习 |
| 分类、类型标签 | 任务 / 灵感 / 笔记 |
| 字段名 | 截止日期 / 创建时间 |
| 单位、数字 | 3 条 / 11月20日 |

把 tab 改成"工作那摊事儿"、把"灵感"改成"灵光一闪"，不是有风格，是让人找不到东西。**风格体现在怎么说一句话，不体现在怎么给东西起名。**

## 三、安全红线：同一口吻的低调档

这五处不许加笑点，但也不许切成"操作失败，请稍后重试"那种公文腔——那会立刻破坏全站一致性。

| 位置 | 为什么 |
|---|---|
| 出错 | 用户已经不爽，再贫就是嘲讽 |
| 删除 / 覆盖确认 | 必须说清"没了就是没了" |
| 涉及金额、日期、次数 | 数字要直白，不能加修辞 |
| 隐私、授权、协议 | 合规文本，一字不能俏皮 |
| 数据可能丢失时 | 用户在焦虑，先给结论 |

三档对比，看第二种为什么最差：

| 写法 | 判定 |
|---|---|
| 操作失败，请稍后重试（错误码 5003） | 公文腔，和全站风格断裂 |
| 哎呀翻车了，我们也在挠头哈哈 | 抖机灵，且在用户不爽时，最糟 |
| **没存上，检查下网络再试** | ✅ 短、口语、不加笑点，和全站是同一个人的口吻 |

**规则：安全位置只做"减法"——去掉笑点，保留口语和短句。**

## 四、为什么一定会走样，怎么防

页面是分批写的，隔几天写一次，每次都会往"中性、稳妥、像文档"的方向漂。这不是谁不小心，是默认倾向。

三道防线：

1. **规范里存 3 条标准样例**（一条正常、一条空态、一条出错）。新页面开工先读这 3 条，照着这个手感写，比读形容词有用。
2. **加页面时先抄手感，再写内容**：把同类位置的现有文案调出来看一眼，别凭空想。
3. **全站通读一次**（见第五节），这是唯一能发现"这一页跑偏了"的办法。

## 五、写完自检（全站通读法）

把全站文案抽成一张表（位置 + 文案），遮住页面名，按顺序读一遍，问六条：

1. 像同一个人写的吗？哪一句突然变味了？
2. 有没有还留着"请输入 / 暂无 / 操作成功 / 请稍后重试"？
3. 安全红线那五处，有没有抖机灵？
4. 每句在字数上限内吗？
5. 有没有一句是为了俏皮，把信息说丢了？
6. 比喻有没有重复到第三遍变啰嗦？（高频位置不许用比喻）

一条不过就改，改完再通读一遍。**通读比逐条检查有效**，因为不一致是"相对"的，单独看每句都没问题。

## 六、好 / 坏对照

| 位置 | 公文腔（无效） | 抖机灵（过度） | 滑稽档（对） |
|---|---|---|---|
| 占位 | 请输入您要记录的内容 | 嘿嘿，快说快说！ | 脑子里刚闪过啥？先丢进来 |
| 空状态 | 暂无数据 | 空空如也，主人快来宠幸我～ | 这儿还空着 |
| 保存成功 | 保存成功 | 叮！你超棒的！ | 记下了 |
| 保存失败 | 操作失败，请重试 | 哎呀翻车了哈哈 | 没存上，检查下网络再试 |
| 筛选为空 | 没有符合条件的数据 | 啥也没有，白筛了哈哈哈哈 | 这个筛法啥也没捞着，换个条件 |
| 删除确认 | 确定要删除吗？ | 手滑了？真删啊？ | 删了就找不回来了 |
| 按钮 | 提交 | 冲鸭！ | 记下来 |

左列是"没有风格"，中列是"风格失控"，右列才是"风格稳定"。**风格稳定的特征是：好笑的地方好笑，该严肃的地方不尴尬。**

## 七、和流程的关系

- **改文案仍是小改动**：直接改代码，不出 HTML 稿。
- **但语气不随页面变**：新增页面属于"继承既有语气"，不是"重新定一次语气"。规范里没写语气档的，先补规范再写页面。
- **新项目的第一批文案必须在 HTML 稿里就用真话写**，不写「示例文字」「Lorem」。稿子里的语气定下来，代码里才会是这个语气。
- **交付说明里要写**：语气档是什么、覆盖了哪些页面、有没有用户指定的例外、有没有安全位置的特殊处理。

## 八、四个反模式（出现就是没执行）

| 反模式 | 表现 | 为什么错 |
|---|---|---|
| 分页分风格 | 首页俏皮，设置页/详情页正经 | 用户会觉得是两个产品拼的 |
| 只改首屏 | 只改了空状态和占位，按钮、提示、toast 还是系统词 | 半套风格比没有风格更显廉价 |
| 靠形容词验收 | "感觉还挺活泼的" | 没法判断，下次一定跑偏 |
| 全站都塞笑点 | 连删除确认、错误提示都要逗一下 | 用户正在烦，等于嘲讽 |
