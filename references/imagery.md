# 图片与视觉素材

页面"平平无奇"有两个原因：**该有图的地方是空白色块**；或者**有图，但图和页面没关系**。

这份只管一件事：**哪里该放图、放什么图、图的规则怎么定。**

---

## 一、先定这张图承担什么

每张图必须能说出一句任务：

- **展示对象** —— 这是什么东西（菜品、食材、成员）
- **解释关系** —— 步骤、流程、位置
- **建立情绪** —— 暖、家常、值得信任

**答不上来，就不要放。**

### 一条可执行的判断标准

> **把这张图撤掉，用户还能不能认出这是什么？**

- **能认出** → 图只是装饰，可以不放（放了也别占大位置）
- **认不出** → 图在承担识别任务，**必须放，而且不能太小**

这条能挡掉大部分"为了好看硬塞图"的情况。

---

## 二、哪些位置值得放图

### 必须放

| 位置 | 说明 |
|---|---|
| **首页/入口大卡** | 一屏最多 2 个，横排；这是产品第一眼的气质来源 |
| **列表项缩略图** | 64–96rpx 见方，圆角；帮助快速识别 |
| **详情页主图** | 4:3 或 16:9，占首屏上半部 |
| **人物 / 家庭头像** | 圆形，48–80rpx |

### 有真实素材才放

- 制作步骤图、菜品图（有实拍才放，别用通用插画凑）
- 分类入口的图（换成图标更好，见下）

### 不要放

- **表单页背景图** —— 干扰输入
- **弹窗、Toast 里** —— 太小，看不出内容
- **tabBar** —— 必须是图标（本地 png，81×81）
- **空状态大插图** —— 除非有整套统一画风，否则一句说明 + 一个按钮更干净
- **每一行列表都强行配图** —— 没素材时，图标 + 文字反而更整齐

---

## 三、没有图怎么办（最常见的情况）

这是"白板感"的真正来源。**不是缺图，是色块里没有东西。**

### 两种合法做法

**A. 色块 + 一个视觉锚点**

色块里至少要有一样"看得见的东西"，占它三分之一的面积：

- 一个大图标（64–96rpx）
- 一个大数字
- 一个短标题（明显大字重）

**只有两行小字的纯色块 = 空板子。**

**B. 预留位 + 统一占位**

先定好图片的**比例和位置**，放同色系的几何占位块，交付说明写"图片待补"。

不要做的：拿不相关的网络图凑、用渐变假装是图、用 emoji 当主视觉。

### 比"有没有图"更重要的两件事

1. **色块之间要有主次** —— 面积不等、或饱和度不同。两个**等大、等亮**的色块并排，一定平。
2. **色块要有形状语言** —— 圆角一致、图标一致、文字对齐一致，纯色块也能好看。

---

## 四、图怎么统一（不统一就是乱）

- **一个产品只用一种视觉语言**：实拍 / 平涂插画 / 3D 渲染，选一种，不混
- **同组图统一**：主体尺度、视角、光线方向、边缘质感。不是套同一个滤镜
- **食物、人物、空间、真实材质，必须用真实位图** —— 不能用矢量图标或纯色块冒充
- **一套里，图要能互相认出来** —— 两个页面的图并排，看得出是同一个产品吗？

### 一个能立刻显高级的做法

**透明物件跨在色块分界上**，让它同时属于两边。一张图跨过两个卡片或两个区块的缝，页面立刻"接得住"，不再是几个方块拼的。

---

## 五、小程序里的六条硬规则

这六条都是"开发者工具正常、真机出事"的类型。

### 1. 必须写死宽高

`image` 不写宽高时会用默认尺寸撑开布局，直接把排版挤乱。

**封面图固定比例**，用 `padding-top` 撑开容器，不让图片自身决定高度：

```css
.cover { position: relative; width: 100%; padding-top: 66.6%; } /* 3:2 */
.cover image { position: absolute; inset: 0; width: 100%; height: 100%; }
```

### 2. `mode` 选错就会变形或裁掉关键内容

| 场景 | mode |
|---|---|
| 卡片封面、缩略图（要填满不露边） | `aspectFill` |
| 步骤图、菜谱图（要完整显示） | `aspectFit` |
| 宽度固定、高度随比例（详情主图） | `widthFix` |

⚠️ `widthFix` 配父级固定 `height` + `overflow: hidden` 会**裁掉图片**，这是最容易犯的组合错误。

### 3. 网络图片必须配 `downloadFile` 合法域名

**`image` 组件加载网络图，走的是 `downloadFile` 合法域名，不是 `request` 域名。**

- 开发者工具勾了"不校验合法域名" → 本地正常
- **真机强制校验 → 没配就白图**

这是"工具里好好的、真机白板"最常见的真实原因。上线前必须在管理后台配好。

另外：网络图**必须 HTTPS**，HTTP 会被拦。

### 4. 不用 WebP

iOS 真机对 WebP 支持不稳定：开发者工具正常、真机空白，极易误判成代码问题。

**统一用 JPG（不透明）/ PNG（需透明）。**

### 5. 体积和数量要算

- 导出**2 倍图**，单张控制在 **200KB 以内**
- **主包 2MB**：本地图只放图标、小 logo；内容图走 CDN
- 长列表加 `lazy-load`（只对 `page` 和 `scroll-view` 生效）

### 6. 加载失败要有兜底

用 `binderror` 换成占位图，避免整片空白破图：

```xml
<image src="{{url}}" mode="aspectFill" binderror="onImgError" lazy-load />
```

## 六、要生成图时

### 提示词按六项写（顺序固定）

1. **主体与形式** —— 什么东西、照片还是插画
2. **构图与留白** —— 主体位置和占比；**留出给文字的那块必须完全干净**
3. **安全距离** —— 主体别贴到文字边缘，留 10% 空隙
4. **背景** —— **直接写页面用的色值**，边缘才能融进去
5. **材质与光** —— 同一页的多张图用同一个光向
6. **排除项** —— 不要文字、logo、界面截图；小物件注明不要投影

### 三条纪律

- **文字、按钮、数字一律由代码排版**，不让模型画（画字会错，且改不了）
- **生成后放进真实页面判断**，不要在图片查看器里看——单独看很好，放进版面常常主体太满、留白在错的地方
- **不拿生成图冒充真实菜品、真实场景、真实人物**

---

## 七、检查清单

- 每张图能说出一句任务吗？
- 把图撤掉，还认得出这是什么吗？（认不出说明图太小或没承担任务）
- 同类图的光线、视角、尺度一致吗？
- 有没有等大等亮的两个色块并排？
- 色块里有没有视觉锚点（图标/数字/大字）？
- 真机上每张网络图都加载出来了吗？（`downloadFile` 域名）
- 主包里图片占了多少？超 1MB 就该往外挪了？

**没有在真机看过图片加载，不许说"图片正常"。**
