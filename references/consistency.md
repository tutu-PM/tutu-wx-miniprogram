# 稿 ↔ 码一致性契约

适用：已经有一版确认过的 HTML 视觉稿（`02视觉风格/原型/index.html`）或用户给的原型，现在要写小程序代码，要求"做出来和稿子一样"。

---

## 零、先承认：像素级"一模一样"不成立

任何人答应你"像素级还原"，都是在骗你。三个原因：

1. **字体不同**：稿子跑在浏览器，代码跑在小程序，系统字体渲染的字宽、字重、行高天然有 1–2px 差异
2. **系统绘制的东西改不了**：原生 tabBar、导航栏、胶囊按钮，高度和样式由系统定
3. **rpx 会取整**：`13px → 26rpx`，在 375 宽机型上正好，在 414 宽机型上必然出现半像素

但这**不是可以放走样的理由**。真相是：

> 一致性分三层，前两层能锁死，第三层只能收到一个可量化的误差里。

| 层 | 能不能锁死 | 靠什么 |
|---|---|---|
| **1 源头**：颜色、字号、圆角、间距的数值 | 能，100% | 数值只有一个出处，稿和码都引用它 |
| **2 结构**：区块顺序、元素数量、文案一字 | 能，100% | 代码照着结构写，不"顺手优化" |
| **3 像素**：最终渲染出来的样子 | 不能，只能收到 ±2rpx | 差异白名单 + 逐点量测 |

**所以"一模一样"的正确提法是：源头和结构必须一样，像素差不超过 ±2rpx，白名单之外不许有差异。** 笼统的"一模一样"，验不了，也没法拒绝。

---

## 一、六条硬约束（每条都能查）

### H1 数值只有一个出处

所有颜色 / 字号 / 间距 / 圆角 / 阴影，只写在 `02视觉风格/design-spec.md` 和全局样式里。HTML 稿和代码都是**引用方**，不是定义方。

- 稿子里临时发明的颜色，一律不许进代码
- 代码里改了一个值，稿子要跟着改；反之亦然
- 两边冲突时**以规范为准**，不是"以稿为准"，也不是"以码为准"

### H2 代码里不许出现裸值

这条能机器查，不用眼看：

```bash
# 裸颜色（token 文件、app.json 除外）
grep -rnE '#[0-9a-fA-F]{3,6}' src --include=*.vue --include=*.wxss | grep -v 'variables\|theme'
# 裸 px（1px 描边例外）
grep -rnE '[0-9]+px' src --include=*.vue --include=*.wxss | grep -v '1px\|env('
# 裸圆角
grep -rnE 'border-radius:\s*[0-9]+rpx' src
```

出现裸值 = 这个页面的数值和稿子已经**没有任何机制保证一致**了，只能靠记忆。

### H3 结构同构，不许"顺手优化"

区块的顺序、数量、嵌套层级，必须和稿子一一对应。

不允许的行为：

- 稿子里三行信息，代码里觉得"时间不重要"删掉一行
- 稿子里分组标题在下，代码里挪到上
- 稿子里一个卡片装三块，代码里拆成三个卡片

要改结构 → **先改稿、再看一次**，不许在写代码时悄悄改。

### H4 文案一字不改

代码里出现的每一句界面文字，都应该能在稿子里逐字找到。

- 标点也算（`……` 不是 `...`）
- 想换说法 → 先改稿，再改码
- 唯一的例外：**数据是假的**（稿子里"共 3 条"在代码里是真实计数），这种属于数据层，不算文案

### H5 状态齐平

稿子里画了空 / 加载 / 出错 / 成功四态的页，代码里四个都要有。

- 稿子有、代码没有 → 漏做
- 代码补了稿子没有的状态 → **回填进稿子**，否则下一轮改版又会漏

### H6 换算表固定，不许凭感觉调

375 宽稿（本项目默认）：**稿上的 px × 2 = rpx**。

| 稿上 | 代码里 |
|---|---|
| 20px 字号 | 40rpx |
| 12px 圆角 | 24rpx |
| 44px 按钮高 | 88rpx |
| 16px 左右边距 | 32rpx |
| 1px 描边 | 1px（不换算） |

**"看着有点小，调大 4rpx"是走样的开始。** 要调就回稿上调，两个文件一起改。

## 二、差异白名单（只有这六类允许不同）

白名单之外的任何不一样，都算 bug，不叫"差不多"。

| 允许不同 | 为什么 | 交付时怎么写 |
|---|---|---|
| 字体渲染的字宽、字重、行高 | 浏览器与小程序字体栈不同 | "标题字宽差约 2px，字体渲染差异" |
| tabBar / 导航栏的高度与内边距 | 系统绘制，随机型变 | "tabBar 由系统渲染，高度与稿差 6px" |
| 原生组件外形（picker、button 重置前后） | 外观受系统控件约束 | "picker 用了原生外观，与稿的圆角不同" |
| 安全区高度 | 刘海与底部横条因机型而变 | "底部操作条避让安全区，比稿高 16px" |
| 滚动条、滚动惯性 | 平台行为 | 一般不用写 |
| 图片解码与缩放 | 编码与插值差异 | "同尺寸下 1px 级差异" |

**这六条之外，只要肉眼能看出不一样，就是没做完。**

## 三、怎么验（四步，别靠"看着差不多"）

### 1. 同宽截图，谁都不许缩放

- 稿子：浏览器 375×812 视口截图（`--window-size=375,812`，`--force-device-scale-factor=1`）
- 代码：模拟器选 375 宽机型（iPhone SE / iPhone 13 mini 都行），截图别缩放
- 两张图宽度必须一致，否则没法比

### 2. 并排看结构，叠图看偏移

- **并排**：查区块顺序、数量、文案有没有少
- **叠图**：两张 50% 透明度叠加，**出现重影就是偏了**，重影越宽偏得越多

叠图是这套里最有效的一步——人眼对"重影"比对齐两次图敏感得多。

### 3. 抽八个点量数字

不要全页面扫，固定量这八个，够抓住 90% 的问题：

| # | 量什么 | 允许偏差 |
|---|---|---|
| 1 | 左右页面边距 | ±2rpx |
| 2 | 区块之间的垂直间距 | ±2rpx |
| 3 | 页面标题字号 | 完全一致 |
| 4 | 正文行高 | ±2rpx |
| 5 | 卡片 / 输入区圆角 | 完全一致 |
| 6 | 主按钮高度 | ±2rpx |
| 7 | 主色十六进制 | 完全一致 |
| 8 | 页面底色十六进制 | 完全一致 |

颜色用取色器直接读像素值，不要凭眼判断"这个青好像深了一点"。

### 4. 代码侧机器检查

跑 H2 那三条 grep。有裸值先修，再谈像素。

## 四、对不上怎么办（三种情况，别混）

| 情况 | 处理 |
|---|---|
| 稿子和规范一致，代码不一致 | **改代码**，这是实现走样 |
| 稿子和规范不一致 | **两边一起改**（改规范 + 改稿 + 改码），只改一边就是又分叉了 |
| 平台就是做不到 | 记进白名单，**写进交付说明**，不许静默放过 |

第三种最容易出事：因为"反正做不了"就不说，用户以为你按稿做了，实际没有。

## 五、交付时写三行

```text
一致性：5 屏与稿逐项核对，8 个量测点偏差 ≤2rpx，颜色完全一致
允许差异：tabBar 由系统渲染，比稿高 6px；标题字宽差 2px
偏离与回改：稿里"待整理"提示条在代码里改成两行，已同步回改稿子
```

**没有这三行，不要说"和稿子一致"。**

## 六、六条常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 直接抄稿子里的 CSS 到工程 | 全局样式污染，改一处改两处 | 取值不取代码，值从规范来 |
| 代码里写了 `#3B7C8C` 这种裸色 | 以后换主色漏掉这页 | 全部 `var(--c-primary)` |
| 觉得行高"太挤"顺手加 4rpx | 稿和码开始分叉，没有回头路 | 回稿上调，两边一起改 |
| 只做理想态就交 | 空 / 加载 / 出错三项缺失 | 按 H5 补齐，稿没有的回填 |
| 拿两张不同宽度的截图比 | 怎么比都不像，白折腾 | 统一 375 宽、统一不缩放 |
| 用"感觉差不多"下结论 | 用户一眼看出来的，就说明差得多 | 抽八点量，用数字说话 |
