# HTML 原型：只验证本轮要决定的事

已有用户确认的页面终稿，且入口、操作和反馈都明确时，**默认跳过 HTML，直接照终稿做真实小程序样板页**。新项目、新增页面、流程跨页或改动范围大，都不是单独出 HTML 的理由。

## 先决定要不要做

| 情况 | 下一步 |
|---|---|
| 没有定稿，要开始设计或开发 | 先请用户确认可用的视觉基准，例如指定参考屏、效果图或存量项目的现有页面。不要把“尚未定稿”当成 HTML 需求。 |
| 用户明确要 HTML 预览 | 按点名的页面、状态和用途制作；只要 HTML 就交付到这里，不启动小程序开发。 |
| 有具体交互需要比较 | 先说清选项和要观察的差异，再做足以比较它们的最小原型。能直接问清的规则不必做演示。 |
| 已确认视觉基准，关键交互明确，用户要开发 | 在项目里实现代表性页面或直接修改指定位置；用运行截图对照基准，不重画 HTML。 |

## 按问题选形式和范围

- **静态**：用户只要看版式、文案或状态差异时，一个局部或一屏就够。确需对照两种状态时才并排，配一句说明，指出差异在哪。
- **可点击**：需要体验操作顺序、返回位置或反馈时，只接通相关动作。例如比较“点标签立即筛选”和“选完点应用”，只需筛选区、结果列表与模拟数据，不必做详情页、登录或真实查询。
- **状态**：只展示影响本次判断的状态。验长标题就用真实长度的文案；验失败重试就演示失败到重试的反馈。不为凑齐四态或整条主流程而加屏。正式实现仍须按 PRD 验证完整状态。

## 单文件做法

放在 `02视觉风格/原型/index.html`（有等价目录则沿用）。双击可打开，不引 CDN、不装依赖、不起服务。用 375px 宽的手机视口对照 750rpx 设计基准，此时 `40rpx = 20px`；内层内容按需滚动。状态栏、胶囊和 tabBar 只保留判断所需的占位。

产品样式引用 `design.md` 的颜色、字号、间距和圆角；存量项目沿用现有组件外观，不顺手改版。文案按 `copywriting.md` 写，用可信的示例内容，不用“测试1”。下面是一个静态对照的最小骨架；只保留本次要看的内容，演示操作时才加本地事件，不接业务接口。

```html
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>收藏列表 · 长标题换行</title>
<style>
  /* 字号取项目规范在 375px 视口的换算值；此处以 28rpx 为例。 */
  :root { --fs-body: 14px; }
  main { width: min(375px, 100%); margin: auto; font-size: var(--fs-body); }
</style>
<main><h1>收藏</h1><p>适合周末慢慢逛的旧书店：从街角的小门进去，上二楼靠窗的位置</p></main>
</html>
```

## 交付与落地

1. 打开预览，指出看哪里、静态对照还是需要点击、要拍板哪件事。例如：“分别试两种筛选方式。多选三个标签时，希望列表每选一次就刷新，还是最后统一刷新？”
2. 如果比较项还要调整，只改对应局部。确认后把选择记入相应的 PRD 或设计规范，已制作的原型留作参考。交互试验不取代页面终稿；与终稿冲突时确认取舍，不擅自改稿。
3. 若用户要求开发，按终稿和确认的交互写真实样板页；不直接搬 HTML/CSS。还原做法见 `prototype-to-code.md`，一致性和交付差异说明见 `consistency.md`。
4. HTML 不是验收。安全区、原生组件、点击区域、动效和真机性能要在小程序里验证，不能以浏览器预览代替。
