# 从 0 开发小程序

适用：还没有小程序代码。走这条时，`SKILL.md` 的六步主流程不变，这份只补充"第 1 步之前"和"第 1–3 步做什么"。

---

## 两个起点，别混

| 起点 | 用户的状态 | 你要做的 |
|---|---|---|
| **A · 定位未定** | 只有一个模糊想法 | 先划 MVP，再进主流程 |
| **B · 定位已定** | 能说清"给谁用、解决什么" | 直接进主流程 |

判断方法：让用户用一句话说"这是给谁解决什么问题"。**说得出来就是 B，说不清就是 A。**

不要因为用户没给正式文档就判成 A。口述清楚就算 B——把他的话复述一遍确认，比要求他写文档有用。

---

## 0. 开工第一步：建目录 + 探 git

**两个起点都要先做这一步，再做别的。** 目录没建，先写的东西最后都要搬一遍。

### 建目录

总文件夹按小程序名命名；没定名字就用 `小程序-2026-11-19`（当天日期）。

```text
我的小程序/
├── 01需求文档/        prd.md
├── 02视觉风格/        design-spec.md / 原型/ / 素材/
└── 03代码/            小程序工程本体
```

现在就把三个一级目录建出来（`02视觉风格` 下再建 `原型` 和 `素材`），后面产物直接往对应目录写，不要再新建 `docs/`、`prototype/` 这类平行目录。

### 探 git

```bash
git --version
git rev-parse --show-toplevel
```

| 结果 | 怎么做 |
|---|---|
| 没装 | 问一次要不要装，给官方下载页，**由用户自己装**；不装就继续，交付说明写"无版本回退" |
| 装了，已在某个仓库内（工作区根常有） | 说明"已在 X 仓库里"，问：跟着现有仓库走（推荐）/ 单独建（会嵌套，不推荐） |
| 装了，不在任何仓库内 | 先不建，**等开始写代码时问一次**要不要建；要就 `git init` + `.gitignore` + 首次提交 |

**同一个项目只问一次。** 没 git 不会卡住开发。

完整规则（每个目录放什么、素材与代码怎么同步、`.gitignore` 模板、已有项目怎么迁）见 `project-layout.md`。

## A 起点：先把 MVP 划出来

### 1. 竞品分析（可跳过）

如果用户愿意，先读 `competitive-analysis.md` 的做法拆两三个同类产品。
用户说"不用看竞品，我就要做 XX"，跳过，直接进第 2 步。

### 2. 划 MVP

只回答三个问题，写成一页，不写长文档：

| 问题 | 要求 |
|---|---|
| 核心闭环是什么 | 用"用户进来 → 做一件事 → 得到结果"一句话说清 |
| 第一步必须先有什么 | 没有它闭环断掉的功能，最多 3 个 |
| 这版先不做什么、以后什么条件下做 | 至少列 3 条，每条带条件；只写"不做"会让范围自己膨胀，也让下一版无从下手 |

**硬规矩**：MVP 不是"功能列表的缩小版"，是"一条能走完的最短路径"。
列表里有 8 个功能但走不通一条闭环，不如 3 个功能走通一条。

### 3. 先定技术栈，再写成 PRD

**从 0 开发没有"现有栈"可沿用，所以必须主动问一次**，不要沉默开工：

> "打算用什么写？我建议**原生 + TypeScript**（只做微信的话最省事）；如果后面要出 H5，或者更想用 Vue / React 写，告诉我。"

用户说"你定"就直接定并说明理由，别甩三个选项让他自己权衡；用户点名了框架就按他的来，只补一句代价。判断规则见 `SKILL.md`「开工前确认技术栈」，三个选项的差别见 `prd.md` 第二节。

技术栈定完，再把它和 MVP 结论一起落成一份需求文档，然后才动代码。**这一步不能跳**——跳过它直接做首页，返在最贵的层（页面清单和结构错了，代码要重写）。

最少写四件事：**几个 tab、多少页、多少功能点、主流程怎么走**。完整写法见 `prd.md`。

用户不想写文档时，你把他的话按这四件事问一遍、替他填成表格，再让他确认一次。**不要因为"他不写文档"就跳过这一步。**

### 4. 定设计规范（PRD 之后，写代码之前）

页面清单定了，才轮到"长什么样"。这一步产出 `02视觉风格/design-spec.md`，不是设计稿：

1. **选一个风格套餐**（暖食 / 清爽 / 卡通 / 专业），一个产品只一个
2. **填满八节**：颜色、字号字重、间距、圆角阴影、按钮三态、容器、图标与字体
3. **在「风格」一节定下文案语气档**：全站统一的一套口吻（如滑稽档）+ 3 条样例 + 例外清单，写法和档位参数见 `copywriting.md`
4. **token 写进全局样式**，`app.json` 的颜色一起对齐

只跟用户确认一次，压成三四行：**哪个套餐 / 主色 / 字体走哪套 / tab 图标从哪来**。

**这一步不能跳。** 跳过它直接写页面，结果是每加一页多几个颜色、多一种圆角——事后统一永远补不完。项目里出现 200 多个颜色的情况，就是这么来的。

完整模板与按钮三态 12 格见 `design-spec.md`。

### 5. 出 HTML 视觉稿（规范定稿之后，写代码之前）

**这一步不能跳。** 规范和 PRD 都是文字，用户没法凭文字判断"东西长这样对不对"。跳过它直接写代码，等于用代码做设计：改一个间距要编译、跑模拟器、截图，一轮十分钟。

做法只有一句话：**一个 HTML 文件，几屏手机界面并排，让用户先看观感。**

- 放 `02视觉风格/原型/index.html`，双击能开，不装依赖
- 按 375 × 812 画，`1rpx = 0.5px`
- 多屏并排，不做页签切换
- 颜色字号间距全部用第 4 步定下的 token，不在稿子里发明新值
- 空 / 加载 / 出错 / 成功四态一起摆
- 文案全部写真话，按定好的语气（`copywriting.md`），不写"请输入内容""暂无数据"
- 不写跳转、不写数据、不写校验

用户点头才进主流程第 1 步；说要改，**先改稿再看一次**。

完整规矩、最小骨架、交付话术见 `html-prototype.md`。

### 6. 小程序特有的一次性判断

划 MVP 时顺手定，避免后面返工：

- **是否需要登录**：不需要就不做（微信登录要资质与配置，且会增加流失）
- **是否涉及用户内容**：有 UGC 就要考虑审核与举报，这会影响提审
- **首屏放什么**：小程序没有浏览器地址栏，用户进来就是首屏，塞不下引导页
- **是否需要分享**：要，就在第一个页面的 `onShareAppMessage` 里返回 `imageUrl` 和标题，别等上线才发现是灰图

## B 起点：口述确认再开工

用户说得清，就复述一遍确认，不要求他补文档：

> "我理解是：给 X 用户，解决 Y 问题，核心动作是 Z。第一期只做这一条闭环，对吗？"

确认后先定技术栈（同样主动问一次，见 `SKILL.md`「开工前确认技术栈」），再落一份**最小 PRD**（技术栈、tab、页面清单、功能清单、主流程），然后按上面的第 4 步定设计规范、第 5 步出 HTML 视觉稿，最后进主流程第 1 步。写法见 `prd.md`、`design-spec.md` 与 `html-prototype.md`。

B 起点不等于跳 PRD——**定位清楚只是省掉了竞品分析和划 MVP，省不掉"这版有哪几页"和"长什么样"。**

## 进主流程：六行怎么填（小程序版）

`SKILL.md` 里的六行，在小程序场景下有几个固定偏向：

| 行 | 小程序场景要点 |
|---|---|
| 1 用户与任务 | 一定是手机、一定在碎片时间、一定是"快速完成一个动作"；不要按"PC 后台"的密度设计 |
| 2 主角与主动作 | 首屏先给内容，不给欢迎语；主动作要在第一屏内不用滚动就能点到 |
| 3 基线与偏离 | 小程序品类的基线是"顶部导航 + 内容区 + 底部 tab"；偏离要说明理由 |
| 4 方向 | 一句话；工作型小程序偏"安静直接"，不要做成宣传页 |
| 5 视觉 | 主色一个、文字灰三档、间距三档、圆角两档，落在全局样式里 |
| 6 动效与状态 | 小程序动效要轻（低端安卓掉帧）；空/加载/出错/成功必须都有 |

### 首屏的硬约束

小程序首屏可用高度 = 屏幕高度 − 导航栏 − 胶囊按钮 − 底部安全区。
按 iPhone SE（568 高）算最保守：**去掉这些之后，真正能用的只剩 400 多 rpx 的视觉空间**。

所以首屏只放得下：一行标题 + 第一排内容 + 一个主动作。放不下就别放。

---

## 第一页选哪个

不要从"首页"开始做。选**闭环里最关键的那一屏**：

- 用户最常做的那件事所在的页面
- 做完了就能验证"这个产品成不成立"的那一屏

首页往往是最难的一屏（要汇总、要入口、要状态），做完它会发现很多前面的决定是错的。

**顺序是：HTML 稿里先画出这一屏 → 用户点头 → 再用真代码写。**

做完第一屏，走通完整状态，再回来做首页。

---

## 常见返工原因（从 0 阶段就要避开）

| 现象 | 根因 |
|---|---|
| 做完发现"不像小程序，像网页" | 用了 `div` 思维、整页滚动、没有用 `scroll-view` |
| 颜色越加越多 | 没有先定变量，每屏现编 |
| 首屏塞不下，最后靠滚动 | 没按 SE 高度算可用空间 |
| 空列表一片白 | 只做了理想状态，没做空状态 |
| 上真机发现图裂了 | 用了 WebP（iOS 真机不稳定）、或图片被父级高度裁切 |

细节见 `platform-ui.md`。
