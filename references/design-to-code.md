# 设计图转前端代码规则

本文件是跨项目复用的**生成规则**，不是任何一个项目的还原方案。以下各节是编制和执行项目方案时的判断依据，不整段复制到项目文件中。

## 调用时生成什么

- **输入**：指定目标项目、本次涉及的页面和已确认的设计稿（默认位于 `02视觉风格/设计图/`，无此目录时按项目实际路径记录）；读取该项目的 PRD、设计规范、平台约束及已有素材清单。已有工程再核对实际组件与路径；新项目不虚构已经存在的组件。不影响编制的缺项记为「待确认」。
- **输出**：在**目标项目**的视觉目录（默认 `02视觉风格/`）生成 `前端还原方案.md`。一项目一份，按页面分节；后续新增页面或更换终稿，只更新同项目相应章节，保留其他页面和已确认的决定。若已有同用途文件则就地更新，不另建副本。不同项目不共用同一份方案。
- **项目文件必须写实**：开头列项目名、目标平台、适用范围；每页列实际终稿、要还原的区域与状态、组件和图片的分工、要先验证的样板、验收条件与尚未验证项。共用约束写一次；有素材交接需求的页面引用本页 `素材.md`，不重复抄资源表。不原样输出占位符。
- **边界**：项目里的配色、导航选择、特殊试验及验收结果只写在项目文件里，不回填母规则。仅要求生成方案时，止于方案，不自动生图、写代码或报告验收通过。

## 1. 锁定还原基准

- 指明唯一终稿版本、页面范围、目标平台和本次允许改的区域。截图是视觉依据，PRD 是数据和行为依据；发生冲突时列出具体差异，遵从用户已经确认的取舍，不悄悄添删功能。
- 记录参考图的内容区域和目标视口。手机外框只为评审，不实现；不能把整张 PNG 的像素宽度直接当成设备逻辑宽度。倍率未知就注明假设。
- 冻结一组对照数据、状态和滚动位置，单独标记允许的原生控件差异。是否沿用原生导航，以目标项目已确认的决定为准，不从其他项目继承。容量讨论不自动改变定稿样例。

## 2. 写代码前，先分清每个元素由谁负责

| 元素会怎么变化？ | 落地方式 | 开发交接要说明什么？ |
|---|---|---|
| 数据或状态会变，用户要点、输入或滚动 | 用真实组件绑定数据和事件；文字、数量和点击区域不切进图里 | 数据来源、状态、点击结果、溢出处理 |
| 外形稳定，但会在多处出现 | 查已有组件或资源；同一份合格资源重复引用 | 实际路径或共用候选；没看到代码不写「已有」 |
| 去掉图后会失去对象辨识或关键视觉特征 | 按 [asset-inventory.md](asset-inventory.md) 列图，不拿整页截图替代实现 | 素材 ID、用途、显示尺寸、裁切限制、状态和缺图回退 |
| 只为看稿方便 | 不进入产品 | 例如手机外框、红框、评审批注 |

判断组件复用和判断图片需求是两回事：一张统计卡可以写一次、用三次；卡里的三个图标仍可能需要三份不同资源。只缺装饰图不阻塞数据和交互开发，但占位版本不能通过最终视觉验收。

## 3. 切图按元素分类，不按整页分类

混合页面逐项判断。小程序项目的 2D 切图操作见 [asset-inventory.md §2.1](asset-inventory.md#21-按视觉对象分类切图)。**有立体感的静态图仍是位图，不等于产品需要可旋转的实时 3D 模型。**

| 类型 | 本版规则状态 |
|---|---|
| 2D 平面元素：图标、标识、平面插画、装饰 | 可执行：先判断要不要切，再做裁切、导出、页面回填和检查。 |
| 拟三维／3D 视觉：靠透视、遮挡或光影呈现体积 | **预留，未定稿。** 试验方案和未解决的问题只记录在对应项目。待目标设备验收、用户认可，并能说明适用边界后，再单独补充通用方法。 |

## 4. 先做有代表性的一块，再扩整页

1. 列出页面的视觉主角，以及第一眼必须看见的业务信息。先对齐整体比例、对齐线和层级，再调描边、圆角和阴影。例如统计承担摘要任务，不因卡片少就放大填满。
2. 选最可能失真的一块，用一个真实素材、实际文案、控件和目标宽度组合验证。不要先批量生产一整套素材，也不要为了迁就一张不合格的图改变终稿布局。
3. 评审通过才扩展到重复区域。重复项按数据生成；位置约束在所属容器内，不按设计截图的全屏坐标逐个贴按钮。窄屏、长名称或数量改变时，仍要能读、能点。
4. 复用项目已有的样式变量和公共控件，代码目录引用素材副本，不覆盖原稿。局部修改只动指定区域；公共组件若会波及其他页面，要先说明。

## 5. 分三项验收，不互相代替

| 验收项 | 怎么验 | 不能据此宣称什么 |
|---|---|---|
| 视觉还原 | 同内容宽度、同数据、同状态和滚动位置，把终稿和运行截图并排；先评主角，再查局部。若数据或占位图不同，标出不能比较的部分。 | 编译成功、元素都在，不代表「看起来一样」。不要各自缩到相同图片高度来掩盖比例偏差。 |
| 功能与状态 | 实际走一遍主流程，再测最容易破坏布局的状态：如空列表、多条数据、长名称或缺图。 | 截图里有按钮，不代表按钮能点；示例中的三条数据不代表支持大容量。 |
| 目标平台 | 选代表性的窄、宽两种视口，检查裁切、热区、可读性和原生元素。微信项目区分 H5、微信开发者工具、真机三种证据。 | H5 对比不等于微信真机通过；不能用放大浏览器视口替窄屏问题作结论。 |

交付说明写明：本次改了哪一块、依据哪版终稿、在哪个平台实际验证、剩余差异与未验项。只有用户认可且能说明适用条件的试验，才升级成通用规则。
