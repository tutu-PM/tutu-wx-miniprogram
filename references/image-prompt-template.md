# 根据 PRD 写页面效果图提示词

在探索页面风格、按已选风格扩页、修改指定底稿或只写提示词时读取。不要用本规则生成单件素材、可交互原型或前端代码。读取 PRD 和本次点名的稿件；有已确认的规范就沿用，没有规范也能探索。用户指定生成方式时不擅自改用其他方式；不可用时说明并停在提示词，不声称已出图。

## 1. 先决定做哪一种

| 用户意图 | 做法 | 停在哪里 |
|---|---|---|
| 只要提示词 | 按下列规则写可独立使用的提示词 | 交付文字，不调用生图 |
| 首次探索，没有指定方向或数量 | 从人群、场景、核心任务推导三个方向；同一代表页各一张独立图，每个方向说明 PRD 依据、可见设计决定和取舍 | 交候选稿，不默认选中，不自动扩页 |
| 指定方向、页数或数量 | 指定条件优先；只点名一种风格时默认一张，要求同风格两版时比较两种表达，不另凑风格 | 只交点名范围 |
| 继承已选风格做其他页 | 每个所需页面默认一张，继承颜色角色、字阶、控件及图标。能传参考图就传，没实际传入只称文字参考 | 不对每页重新探索 |
| 在指定稿上局改 | 锁定底稿版本，先保留原始副本；标出唯一可改区域、改动和冻结项，在副本上另存。紧接局部反馈的“重新生图”仍属局改 | 比对选区外布局、文案、顺序、数据和元素。要求区外像素不变时，用局部合成并逐像素核对；做不到就说明，不冒充精准修改 |

## 2. 填写一条可独立使用的提示词

1. 从 PRD 提取页面任务、主要对象及字段、关键入口、业务状态和主操作。未指定页面就选最能代表产品任务的一屏。只有缺项会改变核心流程或页面含义时才追问；未定的视觉取值可推断，不能据此编造功能。
2. 每一方向固定同页、同样例、同关键文案、同状态、同逻辑视口和镜头；至少在两个视觉维度形成实质差异，不只是换色。风格不限于预设菜单。
3. 先写首屏主角和浏览顺序，再写辅助区的高度、排布、色彩与数字层级。摘要统计优先紧凑，不因为指标少就放大或为凑卡数造指标；压装饰而不是字号和热区。只有查看指标本身就是页面任务时才突出大数字。过多内容表现为滚动延续或 PRD 已允许的下钻，不塞进互斥状态。
4. 每张页面效果图分别套用以下模板，替换括号内容。导出像素、质量等参数另列，不当作逻辑布局尺寸。

```text
为【用户与情境】设计【页面名／界面语言】。用户先看【主角与首要信息】，再通过【入口】完成【核心操作】。使用【已冻结的样例、状态与关键文案】，保留【必要字段和操作】。用【形状、材质、字阶、颜色角色与领域元素】表达【此方向】，使【辅助区】不抢主内容。当前只画【范围与状态】，不加入未定义能力。
单部完整竖屏手机，正面平视、居中、窄边框，四边完整可见；中性纯底，无手持、无斜透视、无拼贴。屏内只画指定页面，外框仅供评审观看。各方向使用相同的设备比例、屏幕占比和视角。
```

局改时用“以【版本】为唯一底稿，只改【区域和内容】，其余【明确列项】冻结”替代探索段。容量讨论、压力测试和其他版本样例不是改图授权。

## 3. 验收和交接

逐张核对入口、数字与业务状态，再核对主次及各方向是否可辨；漏功能、错字和样例错误不进入需求。经用户选定后，只提炼屏内规则；手机外框及其展示要求不进入 `design.md`，连备注也不写。单件素材不加手机外框。方向选择不等于原型确认或真机验收；仅请求效果图时，不改代码或自动启动下一阶段。
