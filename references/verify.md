# 验证与排查

小程序验证的难点不是"怎么做"，而是**分清"代码错"和"环境假故障"**。这份先给验证方法，再给一张假故障对照表。

**先说一件容易被混的事：`02视觉风格/原型/index.html` 里显示正常，不构成任何验证结论。** 那是浏览器里的静态稿，不是小程序。验证只认这三层：

---

## 一、三层验证，能到哪层说到哪层

| 层 | 做什么 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **1 编译** | 编译一次，看有没有报错 | 代码能过构建 | 界面长什么样 |
| **2 模拟器** | 截图看真实渲染 | 布局、文字、状态在模拟器里对 | 真机行为、iOS 差异 |
| **3 真机** | 预览二维码扫码，走关键路径 | 真实表现 | 极端机型 |

**模拟器通过 ≠ 真机通过。** 至少三类问题只在真机暴露：WebP 图片、字体渲染、原生组件层级。

关键路径上前三次验证都过，才算"可以交付"；只到第 2 层，交付说明写"未真机验证"。

---

## 二、截图要查什么

### 自动能查的（工具报一条改一条）

- 编译报错、运行时 console 报错
- 横向溢出（页面被撑宽，出现左右滑动）
- 图片加载失败、显示空白
- 文字被裁切、重叠、只剩孤字
- 对比度过低（浅灰字压浅底）
- 输入框聚焦时被键盘遮挡

### 只能人看的

**三秒测试**：看三秒，能不能说出这一屏的主角是谁、主动作在哪。说不出 → 重点没做出来。

**首屏完整性**：主动作在不在第一屏内、要不要滚动才够得着。

**空 / 加载 / 出错 / 成功**：四个状态都截一次。只截"成功"等于没验证。

**窄屏对照**：至少在 SE 尺寸（375×667 逻辑像素）看一遍。

**与稿子的一致性**（有 HTML 稿或原型时必查）：同宽 375 截图 → 并排、叠图 → 抽八个点量（边距、间距、标题字号、行高、圆角、按钮高、主色、底色）。偏差 ≤2rpx、颜色完全一致、白名单外无肉眼差异才算过。**"看着差不多"不是结论。** 见 `consistency.md`。

### 截图查不了的：动效

截图是静止的，动效必须手上过一遍。三处逐个点：

| 查什么 | 怎么操作 | 不算过 |
|---|---|---|
| 主操作按下 | 按住主按钮不放，再松开 | 只有颜色变、没有缩放；缩了但不回弹 |
| 状态切换 | 点一次筛选、展开一次详情 | 内容瞬间换掉，中间没有任何过渡 |
| 列表增删 | 新增一条、删除一条 | 新项直接出现；删完列表整体跳一下 |

**三个前提要记住：**

- 模拟器比真机顺，**模拟器顺不等于真机顺**，低端安卓看过一次再下结论
- `wx:if` 控制的元素播不出退场动画，写了也不会生效
- 动 `width` / `height` / `top` 的动画，在低端机上表现为卡顿，不是过渡

**验完写进交付说明**：哪三处验过、在模拟器还是真机。没验就写"动效未验证"——代码里有 `transition` 不等于动效正常。

> 截图存下来不等于看过。看的是图，不是"截过了"这个动作。

---

## 三、会存数据的界面：走四步

1. 保存
2. 重进 / 刷新
3. 读回，内容对得上
4. **再走一次失败**（如存储满、权限拒绝），确认用户输入不丢、有明确提示

只做第 1 步的验证，等于没验证。

---

## 四、工具链：有就用，没有就降级

### 探测顺序

1. **官方内建 MCP / Skills**（微信开发者工具 2.x）
   在工具菜单导出 Skill，或在设置 → 安全 里复制 MCP 配置。能力最全：项目开关、编译、模拟器点击输入、截图、console/network 诊断、预览上传。
2. **第三方开发者工具封装**（如 wechat-devtools-mcp）
   把开发者工具 CLI 包成 MCP，提供编译/预览/自动化/截图/日志等聚合工具。
3. **纯 CLI**（`miniprogram-ci`）
   只能编译、预览、上传，**不能看画面**。
4. **都没有**
   让用户在开发者工具里编译并截图给你看。

### 四条规矩

- 探测不到**照常写代码**，只降级验证方式
- 安装、开服务端口、登录开发者工具，**必须由用户完成**，AI 不能自己装
- **"服务在"不等于"能调用"**：服务端口开着但 Token 失效时，调用会鉴权失败（401）。先做一次状态自检，再声称能验证
- 未执行的动作，按 `SKILL.md` 的验证边界表如实写

## 五、假故障对照表（先查这里，再怀疑代码）

这些现象看起来都是"代码 bug"，实际是环境。

### 1. 编译后报"找不到 app.json" / 模拟器红屏 / `routeTo appLaunch timeout`

**根因**：开发者工具正在监听输出目录，而构建命令**先清空该目录再写入**。清空的瞬间工具读不到 `app.json`，于是报错。
用编译型框架（如 uni-app 的 `npm run build:mp-weixin`）时尤其常见。

**处理**：
- 用 **watch / dev 模式**（增量编译、不清空目录），不要用一次性 build
- 或让工具指向 dev 输出目录
- 报错后先让用户点一次"编译"，别急着改业务代码

### 2. 新增工具文件后，页面空白 / 动态绑定全空，静态文案正常

**根因**：热更新时序问题——WXML 换成了新绑定，appservice 还是旧实例。
特征：静态文字显示正常，`{{ }}` 绑定全部为空。

**处理**：让用户重启模拟器或点一次"编译"，**不要先怀疑业务代码**。

### 3. 关掉开发者工具后，改了配置/代理却不生效

**根因**：某些版本的 `cli close` 只关窗口，**进程不退出**，旧的环境变量和代理设置一直被复用。

**处理**：杀进程 → 再打开 → 等待就绪。安全顺序是"杀进程 → 只 open（不 close）→ 等待 → 开始自动化"。

### 4. 自动化连不上（端口不响应）

- 自动化端口是**固定值 9420**，不是随便设的
- 某些 `cli` 子命令没有 `--auto-port` 参数，别硬写
- 端口被其他浏览器占着时，调试端口要换（如 9222 → 9333）
- 窗口被强关过之后，自动化可能附着失败且不报错

### 5. 代理导致的满屏红错

开着系统代理或 VPN 时，开发者工具可能报 `ERR_PROXY_CONNECTION_FAILED`，看起来像代码崩了。
**处理**：先确认是不是代理问题，再动代码。

### 6. Web 预览（H5）右侧永远少一截

用窄视口（390）跑 H5 预览时，右侧固定被截断；换 800 宽就完整。
**这说明是预览视口参数问题，不是布局 bug。** 判断布局问题时先做这个对照，别去改样式。

### 7. 模拟器正常，真机白板

最常见两个原因：
- 用了 **WebP** 图片（iOS 真机不稳定）
- 用了小程序模块作用域里**不可靠的全局对象**（如 `URL`），第三方 SDK 在顶层调用它，直接抛错 → `App()` 不执行 → 整屏白

**第二个的排查特征**：整屏白、只有导航栏和 tabbar、页面 data 只有内部字段。说明**用户代码根本没执行**，不是渲染问题。

## 六、怎么定位"到底哪层错了"

按顺序排除，别跳：

1. **编译过不过** —— 不过就是代码/配置
2. **console 有没有报错** —— 有就先把第一条报错解决（后面的多是连带）
3. **页面渲染出来没有** —— 空白就是"没执行"，去查顶层报错
4. **渲染了但数据为空** —— 查数据来源、时序、热更新
5. **都正常但真机不对** —— 查图片格式、原生组件、机型差异

**只看截图猜原因是最慢的路。** 能读日志就读日志。

---

## 七、诚实条款

| 情况 | 不许写 | 必须写 |
|---|---|---|
| 没编译 | 已编译通过 | 未执行编译 |
| 只读代码 | 视觉已验证 | 未查看实际渲染 |
| 只在模拟器 | 真机已通过 | 未真机验证 |
| 没截图 | 界面正常 | 未截图确认 |
| 只读了 `transition` 代码 | 动效正常 | 未实际触发动效 |

这不是形式，是让别人知道这份结论能信到什么程度。
