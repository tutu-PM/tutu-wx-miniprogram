# 设计规范（design-spec）

**一句话**：这是全项目**唯一**的视觉取值来源。颜色、字号、间距、圆角、按钮三态、容器、图标、字体，一次定完，写进一个文件，后面所有页面只引用不现编。

---

## 什么时候写、什么时候不写

| 情况 | 做不做 |
|---|---|
| 从 0 开发 | **必须做**，在 PRD 之后、写第一行页面代码之前 |
| 原型转小程序 | **必须做**，把原型里的视觉收敛成一份规范（原型不一定是成套的） |
| 已有项目新增功能 | **不新写**，先读出项目现有变量；只补缺的那几项，补完写回同一处 |
| 小改动 | 不做 |

**不做的代价**：每加一个页面就多几个新颜色、新圆角。事后统一永远补不完——今天统一了，明天新页面又散了。这个项目已经有过 215 个不同颜色的先例，就是没定规范的结果。

---

## 它不是什么（先划清，避免做错东西）

| 不是 | 为什么 |
|---|---|
| 不是设计稿 / 效果图 / PSD | 不产出"每页长什么样"的图。每页的视觉由规范和页面骨架决定，不靠图 |
| 不是 PRD | PRD 管"几页、什么功能"；规范管"长什么样"。两份文件，互不替代 |
| 不是汇报材料 | 它只服务一件事：写代码时有唯一的数可抄 |
| 不是一次定终身 | 加新组件时往里补，**但已有值不许随手改**（改一个值＝全项目走查一遍） |

---

## 放在哪

固定放 `02视觉风格/design-spec.md`，和 PRD 分开放：

```text
我的小程序/
├── 01需求文档/prd.md          需求文档
├── 02视觉风格/
│   ├── design-spec.md         设计规范 ← 本文件
│   ├── 原型/index.html        视觉稿
│   └── 素材/                  图片与 icon
└── 03代码/
```

**一个项目只能有一份。** 同一项目里出现两份不同的颜色表，等于没有规范。目录规则见 `project-layout.md`。

## 八节结构（顺序别换，缺一节就会在对应的地方返工）

| 节 | 定什么 | 少了会怎样 |
|---|---|---|
| 一、风格套餐 | 暖食 / 清爽 / 卡通 / 专业，选一个 | 每页各做一套，像四个产品拼起来 |
| 二、颜色 | 1 主色 + 3 档字 + 2 档底 + 线 + 危险 | 颜色越加越多，页面花 |
| 三、字号与字重 | 5 档字号 + 2 档字重 | 层级差不够，整页发灰没重点 |
| 四、间距 | 5 档，8 的倍数 | 间距随手填，看着乱又说不清哪不对 |
| 五、圆角与阴影 | 2 档圆角 + 1 档阴影 | 廉价感：圆角五花八门、阴影忽重忽轻 |
| 六、按钮三态 | 4 种按钮 × 默认/按下/禁用 | 点击没反馈、禁用态看不出来、能连点 |
| 七、容器与卡片 | 列表 / 卡片，三选一表达 | 卡片套卡片、边框+阴影+异色底叠一起 |
| 八、图标与字体 | tab icon 规格、图标来源、字体方案 | tab 图标风格乱、字体加载不出来 |

## 一、风格套餐

**只能是四个套餐里的一个**，取值见 `style-presets.md`。这里只记录三行，并把套餐的"禁忌"抄成检查清单：

```markdown
## 一、风格
- 选定：暖食生活
- 为什么：产品是家庭菜谱，要传达"有饭、有人"，主视觉必须是实拍菜图
- 文案语气：滑稽档（全站统一）——用"你"、主句 ≤12 字、不用"请/暂无/操作/成功"这样的词
- 语气样例：占位「脑子里刚闪过啥？先丢进来」/ 空态「这儿还空着」/ 出错「没存上，检查下网络再试」
- 语气例外：（暂无；用户点名要改的那几处记在这里）
- 禁忌清单（交付前逐条对）：不用高饱和撞色 / 不用纯色大色块占满首屏 / 不用玻璃拟态
```

**不写"简洁""高级""有质感"**。写不出对应套餐就是说不出要什么，先问用户"你希望用户第一眼觉得这是什么感觉"，再落套餐。

**文案语气写"档位 + 3 条样例 + 例外清单"，不把全站文案抄进规范**——文案会一直改，抄进去就得改两处。档位参数怎么定、每处字数上限、好/坏对照见 `copywriting.md`。

**语气是产品级约束，不是每页的选择。** 定完这一节，后面新加的每个页面都继承它；某页想"正经一点"不算合理需求，除非用户点名。

## 二、颜色（1 + 3 + 2 + 1 + 1）

| token | 值 | 用在哪 | 不许用在哪 |
|---|---|---|---|
| `--c-primary` | `#C8754A` | 主按钮、选中态、少量强调文字 | 大面积底色、正文 |
| `--c-primary-soft` | 主色 8–12% 叠白 | 选中行底、标签底、轻提示 | 当第二个主色用 |
| `--c-text-1` | `#241D19` | 标题、正文主信息 | 辅助说明 |
| `--c-text-2` | `#6F5D53` | 次要信息、字段名 | 关键数字 |
| `--c-text-3` | `#A3968C` | 时间、占位、辅助说明 | 需要看清的内容 |
| `--c-bg-page` | `#FFFCF8` | 页面底 | 卡片底 |
| `--c-bg-card` | `#FFFFFF` | 卡片/列表底 | 页面底 |
| `--c-line` | `#EEEEEE` | 1px 分隔线、描边 | 强调 |
| `--c-danger` | `#E54D42` | 删除、失败、红点 | 装饰 |

**状态色不自己调**：成功 `#07C160`、警告 `#FA9D3B`、危险 `#E54D42`、信息 `#576B95`。用户对这四个有固定认知。

**必须同步的第二处（最容易漏）**：`app.json` 的 `navigationBarBackgroundColor` / `tabBar.color` / `tabBar.selectedColor` 读不到 CSS 变量，且只接受十六进制。改主色时两处一起改，交付说明里写明改了哪两处。

## 三、字号与字重

| token | 值 | 用在哪 |
|---|---|---|
| `--fs-page` | 44rpx | 页面主标题（一页最多一处） |
| `--fs-title` | 36rpx | 区块标题、卡片标题 |
| `--fs-body` | 30rpx | 正文、列表主信息 |
| `--fs-sub` | 26rpx | 次要信息、字段值、标签 |
| `--fs-note` | 22rpx | 时间、辅助说明、错误提示 |

四条硬规矩：

1. **相邻层级差 ≥ 6rpx。** 30 和 32 等于没有差别，是白费。
2. **一个页面不超过 4 种字号。** 超过就是层级没理清，不是字号不够用。
3. **字重只用 400 / 500 / 600。** 中文 700 在手机上发黑发糊；300 在小屏发虚。
4. **行高**：正文 1.5–1.6，标题 1.3。不写行高，中文会挤在一起。

---

## 四、间距

| token | 值 | 用在哪 |
|---|---|---|
| `--sp-1` | 8rpx | 图标与文字之间、标签内边距 |
| `--sp-2` | 16rpx | **组内**：一行里的元素之间 |
| `--sp-3` | 24rpx | 列表项内边距、卡片内边距 |
| `--sp-4` | 32rpx | **组与组之间** |
| `--sp-5` | 48rpx | 区块与区块之间、页面左右边距之上 |

**两条判断**：同一个东西内部用 `--sp-2`；两个东西之间用 `--sp-4`。**不要用 20 / 25 / 30 这类值**——一旦允许现编，全项目会出现十几种间距。

---

## 五、圆角与阴影

| token | 值 | 用在哪 |
|---|---|---|
| `--r-sm` | 12rpx | 标签、输入框、小按钮、小缩略图 |
| `--r-md` | 24rpx | 卡片、大按钮、弹层、大图 |
| `--shadow-1` | `0 4rpx 12rpx rgba(0,0,0,.06)` | 卡片需要浮起时（用了阴影就别再加边框） |

**只有两档圆角。** 出现第三种圆角就是没遵守规范。风格套餐是"专业工具"时两档可以收到 8 / 12rpx，但仍然只有两档。

## 六、按钮三态（最常被漏的一节）

**四种按钮 × 三种状态，一共 12 个格子，定完再写页面。**

| 类型 | 默认 | 按下 | 禁用 |
|---|---|---|---|
| **主按钮** | 实心 `--c-primary`、白字、高 88rpx、`--r-md` | 底色压深一档（约 -8% 明度）+ `scale(0.96)` | 主色 40% 底 + 白字，或 `#D8D8D8` 底 + `#FFF` 字；**不要只降透明度到看不清** |
| **次按钮** | 白底 + 1px `--c-primary` 描边 + 主色字 | 底变 `--c-primary-soft` + `scale(0.96)` | 描边和字都变 `--c-text-3` |
| **文字按钮** | 主色字，无底无边 | 透明度 0.6（或变深） | `--c-text-3` |
| **危险按钮** | `--c-danger` 字或底 | 压深一档 + `scale(0.96)` | 同主按钮的禁用规则 |

**按下态必须两个一起给**：颜色变化 + `scale(0.96)`。只改颜色，手指按住时容易看不出来。

实现只有一条路：`hover-class`（小程序没有 `:hover`，`hover-class` 是唯一可靠方式），参数与坑见 `motion.md`。

### 另外三条（不属于三态，但不写就一定出问题）

1. **一屏只有一个实心主按钮。** 两个就是设计错误，用户不知道点哪个。
2. **提交中要有第四态**：按钮宽度不变，文字换成"处理中…"，同时 `disabled` —— 否则用户连点会重复提交。
3. **禁用不等于隐藏。** 不能点的时候要看得见、且看得出为什么不能点（旁边一句 22rpx 的说明），直接消失用户会以为功能没做。

---

## 七、容器：列表还是卡片

**默认列表 + 1px 分隔线。** 只有内容需要"独立成块"（带图、多字段、可单独操作）时才用卡片。

| 判断 | 用 |
|---|---|
| 同一类信息重复出现、字段一致 | 列表 + 分隔线 |
| 每条内容形态不同、要单独操作 | 卡片 |
| 页面只有一块内容 | 不用容器，直接排 |

**用了卡片，只用一种方式表达**：边框 / 阴影 / 异色底，**三选一，不许叠加**。整页全用卡片是最典型的"AI 味"，也是页面显乱的常见原因。

## 八、图标与字体

### 图标

| 项 | 规定 |
|---|---|
| 套数 | **一个产品只用一套**，线性就全线性，实心就全实心 |
| 尺寸 | 约为相邻字号的 1–1.25 倍（30rpx 字配 32–36rpx 图标）；列表项图标 40–48rpx |
| 颜色 | 跟随文字档位（`--c-text-2` / `--c-text-3`），不单独上色；不用多彩图标 |
| 陌生图标 | 旁边必须有文字，不许只放图标 |

### tabBar 图标（独立规格，最常出错）

| 项 | 规定 |
|---|---|
| 格式 | **本地 png**，不用字体图标、不用网络图、不用 svg 直接引用 |
| 尺寸 | 81 × 81 px（约 40KB 以内一个） |
| 数量 | 每个 tab **两张**：未选中（`--c-text-3` 色）/ 选中（主色），共 `tab 数 × 2` |
| 背景 | 透明底；**不要带白底方块**，也不要在图标里画圆角底 |
| 风格 | 与页面内图标同一套；线宽一致（建议 2px 等效） |

**图标从哪来，三条路（按推荐顺序）：**

1. **一套开源图标库**（同一套线性，如 Feather / Lucide / 阿里 iconfont 的成套图标）→ 导出成两个颜色的 png。**这是唯一稳妥的做法**
2. **已有品牌图标** → 让设计出两态 png，不要在代码里用 CSS 改色
3. **生成图（AI 生图）** → **只用于氛围图、插画、主视觉**，不用于功能性图标和 tab 图标。原因：同一套风格不稳定、线宽不可控、导出尺寸与透明边缘不可控，一做就是"四不像"

**禁止**：把两套图标混着用、用 emoji 当图标（各机型显示不同）、拿一张彩色图当 tab 图标（选中态没法区分）。

### 字体方案

小程序**不能像网页那样随便加载字体**：中文全字库 3–10MB，主包 2MB 直接爆；`wx.loadFontFace` 只支持部分格式，且有首屏闪烁。

| 方案 | 做法 | 代价 | 什么时候用 |
|---|---|---|---|
| **A 系统默认（推荐）** | 不加载字体，靠字号、字重、间距做层级 | 无 | 90% 的项目，尤其正文 |
| **B 数字/英文子集** | 只给价格、倒计时、大数字加载一款字体（子集几十 KB） | 需自建子集，中文用不了 | 数字是主视觉时 |
| **C 标题用图** | 少数品牌标题做成图片 | 不可选中、不可翻译、改字要重新出图 | 只有一句 slogan 时，且不再改字 |

**默认选 A，并在规范里写明"不加载自定义字体"。** 选 B/C 要写清是哪几处、为什么值得这一个代价。

字重与行高沿用第三节：400 / 500 / 600，正文行高 1.5–1.6。

## 九、可直接粘贴的 token 块

定完上面八节，把值填进这一段，放到全局样式入口（`app.wxss` 或项目现有的全局样式文件）：

```css
page {
  /* 颜色 */
  --c-primary: #C8754A;
  --c-primary-soft: #FBEFE9;
  --c-text-1: #241D19;
  --c-text-2: #6F5D53;
  --c-text-3: #A3968C;
  --c-bg-page: #FFFCF8;
  --c-bg-card: #FFFFFF;
  --c-line: #EEEEEE;
  --c-danger: #E54D42;

  /* 字号 */
  --fs-page: 44rpx;
  --fs-title: 36rpx;
  --fs-body: 30rpx;
  --fs-sub: 26rpx;
  --fs-note: 22rpx;

  /* 间距 */
  --sp-1: 8rpx;
  --sp-2: 16rpx;
  --sp-3: 24rpx;
  --sp-4: 32rpx;
  --sp-5: 48rpx;

  /* 圆角与阴影 */
  --r-sm: 12rpx;
  --r-md: 24rpx;
  --shadow-1: 0 4rpx 12rpx rgba(0, 0, 0, 0.06);
}
```

**这份和 `app.json` 的颜色是两处**，都要改。规范文件里的值与代码里的值必须一致，不一致以代码为准并回改规范。

## 十、怎么确认"定对了"（先 HTML 稿，再样板页）

**不要出全套设计稿。** 理由：小程序改代码看模拟器比生图快、不花积分；而"每页效果图"一旦和代码不一致，反而变成第二个要维护的东西。

规范定完要过两道确认，**顺序不能反**。

### 第一道 · HTML 视觉稿（确认"值定得对不对"）

用 `02视觉风格/原型/index.html`，把主流程几屏并排画出来，全部引用规范里的 token，空 / 加载 / 出错 / 成功四态齐。

用户看的是：主色够不够、字号层级分不分得开、间距松紧、圆角气质、列表还是卡片。

**这一道改起来最便宜**——改一个 CSS 变量，刷新就看见。所以所有"感觉不对"都应该在这一次说完。

做法见 `html-prototype.md`。

### 第二道 · 真代码样板页（确认"落地没崩"）

HTML 稿点头后再写代码，挑闭环里最关键的一屏（不是首页）：

1. **用真代码写出来**，引用同一套 token
2. 模拟器截图，**关键屏再上一次真机**截图
3. 和 HTML 稿并排给用户看一次
4. 用户点头 → 铺其他页面；说不对 → **只改规范 + 稿子 + 这一屏**，别边铺边改

**并排不是"看着像"。** 同宽 375 截图、叠图看有没有重影、抽八个点量数字（边距 / 间距 / 标题字号 / 行高 / 圆角 / 按钮高 / 主色 / 底色），偏差 ≤2rpx。做法与允许差异清单见 `consistency.md`。

**为什么还要这一道**：HTML 稿在浏览器里跑，验不了字号在真机上会不会裁切、按钮 88rpx 够不够点、图在 750 宽下变形没有、低端安卓掉不掉帧。

### 两道都过，才算"视觉定稿"

**生图在这里的合法用途**：只用来出"图片素材"（菜品图、插画、氛围图、空状态插画）。它不是设计稿，不改界面结构、不定字号、不定间距。

---

## 十一、四条可机器检查的规矩

交付前搜一遍代码，这四条必须为 0：

1. **页面样式里出现裸十六进制颜色**（`#` 开头，token 文件除外）
2. **页面样式里出现裸 rpx 尺寸**（`32rpx` 这种；`0`、`100%`、`1px` 描边除外）
3. **一个页面出现 3 种以上圆角 / 5 种以上字号**
4. **`app.json` 里的颜色和 `--c-primary` 不一致**

前两条能搜出来，后两条靠扫页面对比。**四条都过，才算"规范被真正执行"**，而不是"规范写了"。

具体 grep 命令见 `consistency.md` 的 H2——那四条是"稿与码像不像"的基础，这里过不了，后面的像素核对没有意义。

## 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 规范写得很全，代码里照旧写字面值 | 规范和代码两套值，越走越远 | 交付前跑第十一节四条检查 |
| 每个页面自己定一次"这一屏的主色深浅" | 出现 5 个近似主色 | 浅色只用 `--c-primary-soft`，不派生新色 |
| 只定颜色不定按钮三态 | 点击没反馈、禁用态靠猜、能连点提交 | 第六节 12 个格子填满 |
| 用生成图做 tab 图标 | 两态对不上、风格不一 | tab 图标只用开源图标库导出 |
| 加载中文网络字体 | 包体积爆 / 首屏白字 | 系统字体，除非数字是主视觉 |
| 出全套设计稿再开发 | 图与代码两张皮，改一处改两遍 | 先 HTML 稿，再真代码样板页，两道确认 |
| 跳过 HTML 稿直接写代码 | 用代码做设计，改一个间距跑一轮编译 | 先出一版 HTML 稿 |
| 中途改规范里的已有值 | 全项目走查，改不干净 | 已有值只能补不能改；确需改按"全量替换"处理并说明 |
